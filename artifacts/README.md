# ReFlow artifacts

Results and reference scripts of the ReFlow paper. The implementation is the `schema_reduction` module of the `process_mining` crate in this repository, and the evaluation examples are listed in [`../process_mining/examples/README.md`](../process_mining/examples/README.md#reflow-evaluation).

## What ReFlow produces

ReFlow turns a log into a **tagged OCEL**: every event-to-object tuple carries a tag, `flow` or `nonflow`, encoded as a prefix on the tuple's qualifier -- `!` means `nonflow`, no prefix means `flow`, and a `+` prefix marks a participation an expansion wrote -- so a tagged log is an ordinary OCEL 2.0 log and nothing is deleted.

- The **flow projection** is the tagged log with the `nonflow` tuples dropped: `flow_projection(&tag(..))` in Rust, or the `flowProjection` deposit in the UI. Discovery reads it.
- The **full projection** is the tagged log with the tags dropped: `full_projection(&tagged)`. It returns the input log, and every analysis other than discovery reads it.

ReFlow runs in two cases. In the **reduction** case the candidate cells are the recorded ones and no tuple is added. In the **expansion** case the candidate cells also hold unrecorded cells that a relation admits, and the participations those cells contribute are written under the `+` prefix; the `+exp` columns of Table 1 report it.

## Layout

| directory | content |
|---|---|
| `logs/` | put the nine corpus logs here, see `logs/README.md` for the download list |
| `results/stats/` | the JSON files every example writes; the paper's tables and numbers are read from these |
| `results/ground_truth/` | the activity orderings derived by hand from the CPN Tools models of Order Management and Container Logistics |
| `results/models/` | OCPNs discovered from the recorded log and from the flow projection, plus the repaired (annotated) net |
| `results/reduced-logs/` | the flow projections of the corpus, as OCEL 2.0 (directory name kept, the published result files reference it) |
| `code/` | Python reference implementation, figure generators and baselines, see `code/README.md` |

## Reproduction

1. Download the logs into `logs/` under the file names in `logs/README.md`.
2. Build and run the tool that writes the assignments and the replay scores:
   ```bash
   cd process_mining/tools/ocpn-quality
   cargo run --release
   ```
   It needs a checkout of `ee-precision` next to this repository (see its `Cargo.toml`).
3. Run the examples of the paper from `process_mining/`, e.g.
   ```bash
   cargo run --release --features "ocel-sqlite,token-based-replay" --example cross_instantiation
   cargo run --release --features "ocel-sqlite,token-based-replay" --example eval_instruments
   cargo run --release --features "ocel-sqlite,token-based-replay" --example exact_gap
   cargo run --release --features "ocel-sqlite,token-based-replay" --example type_deletion
   cargo run --release --features "ocel-sqlite,token-based-replay" --example ground_truth_reverse
   ```
   Every example accepts log paths as arguments, and `REFLOW_LOGS` and `REFLOW_STATS` override the default directories.
4. The figures of the paper are generated by `code/make_cell_grid.py`, `code/make_schema_graph.py` and `code/make_expansion_figure.py` from the logs and `results/stats/<log>.keepsets.json`.

## Order Management, end to end

The paper's running example is `logs/order-management.xml`. Two commands reproduce its numbers:

```bash
cd process_mining
# 14 flow, 3 involved, 23 implied of the 40 recorded cells
cargo run --release --features "ocel-sqlite,bindings" --example schema_census -- \
    ../artifacts/logs/order-management.xml --json          # tally.flowCells / involvementCells / impliedCells
# OCPN arcs: 163 recorded, 40 on the flow projection
(cd tools/ocpn-quality && cargo run --release -- ../../../artifacts/logs/order-management.xml)
```

`ocpn-quality` writes `results/stats/order-management.keepsets.json` (keys `flow`, `inv`, `absent`, with `absent` naming the implied cells: the key is the stored file format the figure scripts read) and `order-management.scores.json`, whose per-type `arcs.recorded` and `arcs.reduced` sum to 163 and 40.

## Parameters

Every constant the pipeline reads is in one file, [`results/params.json`](results/params.json), rather than repeated in each result file. It is the value of `schema_reduction::knobs()`, printed by

```bash
cd process_mining && cargo run --release --features "ocel-sqlite,bindings" --example schema_census -- --params
```

Table 1 of the paper reads `cross_instantiation.json` (size blocks, orderings, `+exp`), `type_deletion.json` (the deletion baseline) and `eval_instruments.json` (preserved orderings and runtimes). The fitness and precision paragraph reads `<log>.scores.json`, the ground truth paragraph `ground_truth_reverse.json` with `results/ground_truth/`, and the threshold paragraph `theta_sweep.json` and `determination_sweep.json`.
